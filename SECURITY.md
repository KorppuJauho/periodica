# Security

Periodica is meant for a home LAN. Do not expose it to the internet. For remote access use a VPN (WireGuard, Tailscale) or an authenticated HTTPS reverse proxy, and set `SECURE_COOKIES=true` when you do.

## Threat model and mitigations

| Risk | Mitigation |
|---|---|
| Deleting or linking the wrong torrents | Only one exact, non-empty qBittorrent category is in scope. Every torrent list is filtered again on our side. A delete re-fetches the torrent by hash and re-checks category and completion right before the call. Hashes are validated strictly, so `hashes=all` can never be sent. |
| Unwanted network connections | `OFFLINE_MODE=true` forces qBittorrent, Jellyfin and the scan API off at runtime (they can't be switched on in the UI), and the HTTP client refuses to create any connection while it is set. |
| Hostile file names against user patterns | Naming patterns are compiled from escaped literal text and a fixed set of placeholders; the user's text is never used as a regular expression. Patterns are limited in length and in free-text placeholders, and a publication name taken from a file goes through the same folder-name checks as any other. |
| Hostile archives (CBZ, EPUB) | A file's header must match its format. Only the zip directory (at most 10,000 entries) and at most one entry per file are read, in memory, with size (20 MB) and compression-ratio limits; nothing is extracted and entry names are never used as paths. EPUB XML is size-limited and refused if it has a DTD or entities; the cover path must stay inside the book. Cover images are checked by their magic bytes and copied, never decoded. RAR (CBR) files are recognised by their header only and never opened. |
| Repairing the library (Library health) | A scan only reports damaged issues; nothing is changed until the user presses Fix. Replacing a copied PDF with a link happens only in issue folders carrying the marker, after a confirmation, by linking the download to a temporary name in the same folder and renaming it over the old file in one step (symlinks are refused). |
| One library touching another's files | Each library's category and name are unique, and no library's source or destination folder may lie inside another library's folders (checked when saving and again before every scan; overlapping libraries are skipped). Deletes use the torrent's own library's category and remove issue folders only under that library's destination. A disabled library is never scanned and its issues are never deleted. The Add-library wizard only reads from qBittorrent and Jellyfin. |
| Linking the wrong files in folder mode (no qBittorrent) | The whole source folder is in scope, so it must be dedicated to these downloads. Symbolic links are never followed, hidden entries are skipped, and walks are capped (depth and file count). Nothing can be deleted in this mode: every delete path requires qBittorrent, and folder downloads carry no category, so they can never pass the delete check even after switching back. A finished-download call's path must resolve inside the source folder. |
| Runaway deletes (bad setting or path mapping) | Automatic delete is off by default. It needs a dry-run preview and an explicit *arm*, and it disarms whenever a related setting changes. Expired items wait out a grace period in a queue where you can keep them. If more are due than the per-run limit, nothing runs until you approve the batch. A pack torrent is deleted only when every paper in it has expired and it contains nothing unexpected. If qBittorrent is unreachable, nothing is deleted. |
| Deleting user files | The app never writes to or deletes from the downloads folder; qBittorrent deletes its own files. In the library it deletes only issue folders carrying its `.periodica.json` marker, at the expected depth. |
| Malicious file names in torrents | Paths from the API are checked on their raw components (no absolute paths, `..`, empty parts or backslashes). Names are NFC-normalised and sanitised. Every resolved path must stay inside the configured root, and symlinks are refused in both trees. |
| Malicious PDFs | A file must start with `%PDF-` before it is linked. Covers are rendered by `pdftoppm` in a separate process: no shell, fixed arguments, minimal environment, 60 s timeout, and CPU/memory/file-size/open-file limits. The output must be a JPEG under 10 MB. PDFs are never parsed inside the web process. |
| SSRF / credential leaks via the qBittorrent or Jellyfin URL | Only http/https URLs without credentials are accepted. Hosts must resolve to LAN, loopback or CGNAT addresses (re-checked on every request) unless you explicitly allow others. Redirects are never followed, proxy environment variables are ignored, and timeouts and response-size caps apply. |
| Web UI attacks | There are no default credentials: the first run creates the admin account. Passwords use Argon2id. Sessions live on the server behind `HttpOnly` + `SameSite=Strict` cookies. Every POST needs a CSRF token and an `Origin` check. Failed logins trigger an exponential lockout. A strict CSP (no inline scripts, no third-party assets) plus `X-Frame-Options: DENY`, `nosniff` and `no-referrer` headers are set. Templates are auto-escaped, redirect messages are fixed strings, and the title format blocks attribute access. |
| Secrets | The qBittorrent password and Jellyfin/API keys stay in SQLite (file mode 600) under `/config`. They are never shown in the UI or written to logs. |
| Container escape / lateral movement | Runs as a non-root UID, with a read-only root filesystem, `cap_drop: ALL`, `no-new-privileges`, and memory and PID limits. The only writable mounts are `/config`, `/data` and a tmpfs `/tmp`. |
| Supply chain | Few dependencies, locked with hashes and installed as wheels only. The base image is pinned by digest. GitHub Actions are pinned by commit SHA. CI runs ruff, mypy, bandit, pip-audit, the tests (also inside the runtime image), a hardened smoke test and a Grype image scan. Dependabot watches pip, Docker and Actions. |
| Metadata from the internet | None is fetched. Covers come from the PDF itself. Jellyfin's own online providers are a separate choice; see docs/jellyfin-setup.md. |

## Reporting a vulnerability

Please use GitHub's **private vulnerability reporting** on this repository (Security -> Report a vulnerability)
rather than a public issue. This is a spare-time project, so a fix may take a while; you will get an answer
either way.
